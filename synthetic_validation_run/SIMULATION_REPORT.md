# Synthetic Pipeline Validation Report

> ⚠️ **This entire document describes a run on simulated, non-patient signals.**
> It exists to prove the CardioFusion-AI codebase runs end-to-end and to show
> what real tables/figures will look like once real data is substituted in.
> **None of the numbers below are cardiovascular risk detection results and
> must not be cited, quoted, or reported as such in a paper, poster, or
> repo README.** See "Why synthetic, and what it does/doesn't prove" below.

Generated by `synthetic_validation_run/run_validation.py` in this repository.

---

## 1. What was run

1. **Data**: 300 simulated ECG+PPG recording pairs (150/150 class balance),
   generated by `generate_synthetic_data.py`. "Class 0" and "Class 1" are an
   *arbitrary* simulated split (different heart-rate mean and beat-to-beat
   jitter used to generate the waveform, plus more sensor noise for class 1)
   — not a model of any diagnosed condition.
2. **Preprocessing**: the real `preprocessing/ecg/` and `preprocessing/ppg/`
   pipeline in this repo — filtering, R-peak/systolic-peak detection, HRV/PRV
   feature extraction. No shortcuts; this is the same code you'd run on real
   data.
3. **Model**: PyTorch wasn't installable in the environment that built this
   (no internet access), so the deep-learning fusion architectures in
   `models/` were **not** run here. Instead, the 10 engineered HRV/PRV
   features (5 from ECG, 5 from PPG) were fed to two classical scikit-learn
   baselines — Logistic Regression and Random Forest — as a stand-in that
   could actually execute, so the full pipeline could be verified end-to-end.
4. **Evaluation**: `evaluation/evaluate.py`'s real metric functions
   (accuracy, precision, recall, F1, sensitivity, specificity, AUROC), plus a
   simulated-PPG-dropout robustness sweep.

## 5. Why synthetic, and what it does/doesn't prove

**What this proves:** the preprocessing, feature extraction, evaluation, and
visualization code in this repository runs correctly end-to-end, produces
sane values (e.g. recovered heart rates matched the generator's ground
truth to within a few bpm), and degrades sensibly under a missing-modality
stress test. That's a meaningful engineering validation.

**What this does not prove:** anything about real cardiovascular risk
detection performance. The "classes" here were generated from a hand-picked
statistical split with no clinical grounding, the sample size is small and
fully synthetic, and the deep-learning fusion models described in the README
were never executed (no PyTorch in this environment). An 81%/0.92-AUROC
number from this run has no bearing on what you'll get from PTB-XL/MIT-BIH/
BIDMC/PulseDB data — it could be higher or lower, and won't be known until
you actually run it.

**Recommended path to real results:** install `requirements.txt` (ideally in
Google Colab or a local machine with GPU access, since PyTorch training is
heavier than this sandbox can run), download the real datasets per
`datasets/README.md`, and run `training/train.py` against them. Use this
report's tables/figures as a template for structure, not as a source of
numbers.
